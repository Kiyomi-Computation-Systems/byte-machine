# Changelog

All notable changes to byte-machine are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **The benchmark runner's documented command now runs.** The command given in
  `bench/runner/benchmark.sps` and in its artefact's `exact-command` failed with
  "not found in source directories": the source launcher empties
  `source-directories`, and `load-program` searches them for a relative path
  that does not begin with `./`. The runner now documents and records
  `--program ./bench/runner/benchmark.sps`. The committed baseline keeps the
  string it recorded, with a note in the benchmark reference that it never
  ran as written; none of its measurements change.

## [0.7.0] - 2026-10-01

A minor: two accessors on the parser-error record, asked for by a consumer
that counts span bytes against a size limit. **No regeneration is needed** — the generated-runtime ABI stays 9, and
the emitted text and every golden are unchanged. A parser generated by 0.6.x
gains the two accessors by loading this runtime, unless its output binding is
one of the two new names (see *Changed*). The allocation audit now also
derives the runtime ops emitted code can call and fails for any its inputs
never reach, and every mutation pin in six lanes now names its own mutant.

The diagnostic census is unchanged at 33 codes / 60 sites. The mutation lane
goes from 77 passes / 651 mutations to 78 / 680.

### Added

- **An error records the span it abandoned**
  ([issue #145](https://github.com/Kiyomi-Computation-Systems/byte-machine/issues/145)).
  When a parse error stops the parser with a span open, no final fragment is
  flushed, so the bytes the span took in the failing feed never reached
  the application. An embedder that counts a span's bytes, for a size limit on
  a request target say, got an answer that depended on how the network split
  the input. Two accessors on the parser-error record now say what was
  withheld. `parser-error-span` names the abandoned span, and
  `parser-error-span-offset` is the stream offset where its withheld bytes
  begin. Both are `#f` when no span was open. With the span's data callback
  bound, the delivered fragments followed by `[span-offset, parser-error-offset)`
  are the span's bytes up to the error, however the input was split into feeds.
  A new lane asserts this in both executors over every schedule of up to three
  feeds, on a byte-dispatch span, a keyword table inside a span and a counted
  body inside a span.

  Internally, a span delivery now advances the span's mark to the fragment's
  end; the code had dropped this while nothing could observe it. Without it, a
  data callback that fails would see its own bytes reported as withheld.
  **No regeneration is needed.** The generated-runtime ABI stays 9, the
  emitted text and every golden are unchanged, and the two values are filled
  where both executors hand an error back. Every parser-error record carries
  the two new members, so the cross-lane error projection grows from six
  members to eight.

- **The allocation audit is a census of the runtime ops emitted code can call.**
  [Issue #139](https://github.com/Kiyomi-Computation-Systems/byte-machine/issues/139)
  was an op the audit never ran, so the claim that generated per-byte paths
  construct no lists now rests on a measurement, not on the fixture. The lane
  derives the op set from `compile.sls`'s emitted-text literals: twelve
  procedures and one constant. It counts, on a counting twin of each audited
  machine, which ops its inputs reach. Six had never run under it. Three new
  witnesses now reach them: a machine error, a callback failure, and the
  emitted keyword arm. Each asserts that the event costs the same however many
  bytes precede it, against a live control. A totality row fails for any
  derived op no witness reaches. The lane also asserts that no op is entered
  per byte of a header value or per matched keyword byte.

### Changed

- **`parser-error-span` and `parser-error-span-offset` are refused as output
  bindings**, like every other runtime export. A
  generated library imports `(byte-machine runtime)` whole, so a binding with
  either name would collide with the import.

### Fixed

- **Every mutation pin in six lanes names its own mutant and no other.** Each
  pin in `unit.runtime`, `property.differential` and the field, callback, span
  and sequence-node differentials was judged against every mutant in its lane;
  forty are re-pinned on measured records. In nine places one mutant's records
  all sat inside another's; there a check now asserts a pair, or a fixture
  carries both cases, so that each reports its own value. Test-only: no source
  changes, and the mutation lane stays at 78 passes / 680 mutations.

## [0.6.1] - 2026-09-26

A patch: one runtime fix, from a consumer's allocation gate. **No
regeneration is needed** — the generated-runtime ABI stays 9, and the emitted
text, every golden and every public API are unchanged. A parser generated by
0.6.0 picks the fix up by loading this runtime.

The diagnostic census is unchanged at 33 codes / 60 sites. The mutation lane
goes from 76 passes / 637 mutations to 77 / 651.

### Fixed

- **A keyword walk no longer copies its matched prefix on every byte**
  ([issue #139](https://github.com/Kiyomi-Computation-Systems/byte-machine/issues/139)).
  `byte-machine-keyword-step/v1` built the prefix it had matched as a new list
  for each byte it consumed, so a header name matching k bytes of a keyword
  allocated about k²/2 pairs. Downstream this was 2,944 B for one
  `Connection: keep-alive` field, and 138 times a request's own size for one
  that repeated a near-miss of `Transfer-Encoding`. The walk now makes one pass
  over the table. It compares each keyword in place against the parked prefix
  and then this feed's bytes, and stops where the longest shared prefix ends,
  which is where greedy consumption stopped. It builds a list only for the
  `need` answer that parks one, and allocates a flat 64 B, its answer, however
  much of a keyword it matched. Time per walk now grows linearly in k instead of
  quadratically: 17.8 ms against 267 ms for 200,000 walks at k = 17.
  `bench/runner/keyword-walk.sps` reproduces both columns.

  **No regeneration is needed.** The `/v1` contract, the ABI, the emitted text
  and every golden are unchanged.

  The allocation audit could not see this: its fixture has no keyword table,
  and both of its slopes hold a header name's match length fixed. It now
  asserts a third shape: what one walk allocates does not depend on how much
  of a keyword it matched, on how long a prefix it resumed with, or on how long
  a prefix it parks unchanged. A live control, the pre-fix walk, shows the
  lane can see the difference. The keyword differential gains a GET/SET table,
  one input for each wrong way the walk could compare, count, choose or park,
  and two direct op cases.

## [0.6.0] - 2026-09-18

**The emitted dispatches stop being linear scans**, at four depths, plus the
allocation the last of them hid.

**BREAKING for generated parsers: the ABI is 9.** Regenerate. An ABI-8 library
decodes the callback seam's answer with `car`, which a fixnum does not answer,
so the mismatch is refused at construction. `byte-machine-callback-step/v1` and
`byte-machine-span-fragment-step/v1` are retired to tombstones and replaced by
`/v2`.

Nine rounds of sixteen thousand on `tarm64osx`, generated lane:
`long-exact-sequence-matching` 118 -> 60 ms, `many-small-headers` and
`dense-byte-dispatch` 90 -> 51, `byte-at-a-time-fragmentation` 39 -> 32.
Per-header allocation 128 B -> 0. Downstream, `chez-httparse` parses a 308-byte
request at 175,342 msg/s where it parsed at 14,925 before this release, with
its live llhttp differential unchanged at `agreed=9557` throughout.

**The feed-entry search ships without meeting the admission rule** (see
*Added* below) -- 22% on one admissible workload where the rule asks for 20% on
three. The bench machine is 217 states with no keyword table, so every workload
but the byte-at-a-time one crosses the feed entry once per message.

No verifier diagnostic is added or removed (33 codes, as in 0.5.0).

### Changed

- **The feed entry is a search, not a scan.** The fourth and last of the
  linear scans this release removes, after the state, byte and goto-target
  dispatches below: `%dispatch` answers the only target that genuinely cannot
  be a literal -- the state comes from the parser -- but it did not have to be
  linear about it. It is now a balanced binary search over the state ids,
  ceil(log2 N) comparisons where the scan averaged N/2 arms, with the same tail
  calls at the leaves so the direct state-to-state jumps are untouched.

  A jump table is rejected with a reason: a vector of the state procedures is
  O(1) but makes every one of them escape, and they close over `exec`'s
  parameters, so Chez would build N closures on every `exec` entry -- which is
  the per-feed path this exists to make cheaper.

  Measured in situ on the largest machine the ecosystem generates
  (`chez-httparse`, 530 states, keyword tables), three runs each side with a
  load marker: whole buffer **167,224 -> 176,522 msg/s (+5.6%)**, byte at a
  time **25,141 -> 44,395 (+77%)**.

  **On this project's own benchmark it is -22.0% on
  `byte-at-a-time-fragmentation` and flat on the other four admissible
  workloads, which does NOT meet the three-workload admission bar.** The
  reason is the instrument: the bench machine is 217 states with no keyword
  table, so its whole-buffer workloads cross the dispatch exactly once per
  message and there is nothing there to remove.

  Emitted text grows 9.6% (118,023 -> 129,379 bytes for the HTTP golden). No
  fingerprint moves.

- **A callback outcome is the object, not a list naming it** -- ABI 9. The
  callback seam answered `(goto TARGET)`, `(pause)` or `(failure CODE DETAIL)`:
  two conses, 32 bytes, on every crossing, and an HTTP grammar crosses it four
  times per header. It now answers the outcome itself -- a target, the
  `callback-pause` singleton, or the `CallbackFailure` the application already
  allocated -- and both lanes decode with the same two predicates, the three
  cases being disjoint by type. The single producer is unchanged; what is gone
  is a tag that told a consumer nothing the object did not already say.

  **Per-header allocation in the generated lane goes from 128 bytes to zero**,
  callbacks bound or disabled, now asserted. Per-message allocation stops
  depending on the message's shape: `long-exact-sequence-matching` 8 800 ->
  1 168 B, `many-small-headers` 5 216 -> 1 168, `pipelined-requests` 3 040 ->
  1 168, `short-normal-requests` 1 504 -> 1 168. Five shapes, one figure.

  **BREAKING for generated parsers.** `byte-machine-callback-step/v1` and
  `byte-machine-span-fragment-step/v1` are retired to tombstones and replaced
  by `/v2`, and the emitted ABI literal is 9. An ABI-8 generated library is
  refused at construction with the usual clean mismatch; regenerate it.

- **A goto target is chosen at run time from a set fixed at emit time.** The
  third instance of the linear-scan defect: the three arms that call
  application code answered `goto` through `%dispatch`, the last linear `case`
  over every state id. The target is not known until the callback returns, but
  the SET is -- continue, a declared branch, or the default, all of them
  literals the emitter wrote into that very call -- so the arm tests them and
  jumps directly, continue first. `%dispatch` stays as the clause no
  construction reaches.

  Generated lane, nine rounds of sixteen thousand iterations, `tarm64osx`,
  with the callback-outcome change: `long-exact-sequence-matching` 118 -> 59 ms,
  `many-small-headers` 90 -> 51, `dense-byte-dispatch` 90 -> 51,
  `long-method-target-header-spans` 69 -> 67. Three admissible workloads past
  the 20% bar. `byte-at-a-time-fragmentation` costs 5.1% (39 -> 41 ms) --
  real, below the significance bar, and not attributed.

### Added

- **The allocation audit grows a second slope, per HEADER**, with its own live
  control. The per-byte slope holds the header count fixed, so it could not
  see 128 B/header and the figure landed in an intercept that is deliberately
  never divided by anything. The new leg asserts zero both with callbacks
  disabled and with callbacks bound.

- `bench/runner/benchmark.sps` takes `BYTE_MACHINE_BENCH_EXECUTORS` (`both`,
  the default, or `generated`). The interpreter is ~200x slower and is ~95% of
  a run, none of it the thing being optimized; this keeps the A/B loop on the
  shipped instrument instead of a hand-rolled script. The setting is recorded
  in the artefact, so a partial run cannot be mistaken for a baseline. The
  committed baseline is always taken with both.

- **A byte class is a range, and a linear scan of its members is not.** The
  same linear-scan defect as the state dispatch, one level down in the byte
  dispatch. Over a
  94-byte set, a flat `case` costs 21.60 ns for a lowercase letter -- which is
  what HTTP is mostly made of -- against **1.25 ns** for range tests. A
  dispatch now renders one clause per run of consecutive bytes sharing a
  destination, which is the source byte class that lowering had flattened.

  Generated lane, five rounds of two thousand iterations, `tarm64osx`:
  `long-method-target-header-spans` 85 -> 8 ms, `long-exact-sequence-matching`
  40 -> 14, `many-small-headers` 37 -> 11, `dense-byte-dispatch` 37 -> 11. Four
  admissible workloads, none regressing. Downstream a request target scans at
  7.2 ns/byte where it scanned at 27.5, and the ratio against llhttp's own
  bench mode falls from 104x to 44x.

  **The emitted text shrinks 44%**, which pays back most of what the
  state-procedure change cost: a `case` arm per byte was most of what a
  generated parser was made of. No fingerprint moves; the IR is untouched.

  A grouped datum list, the obvious alternative, is worse than what it would
  have replaced: it costs 57.40 ns,
  because `memv` over 94 elements loses to the nested-if expansion `case`
  already gets.


- **A state is a procedure, not a case arm.** `render-machine` emitted one
  `(case st ...)` re-entered per transition, and Chez compiles a large `case`
  over integer keys as a **linear scan** -- about 0.31 ns per arm skipped,
  measured against 10.4.1, identical at every optimize level. A machine's
  per-byte cost therefore depended on where the state numbering happened to
  place its hot states. Every state now renders as a procedure and a transition
  to a target known at emit time is a direct tail call: 0.80 ns against 185.85
  ns for the same state, and independent of its id.

  Generated lane, five rounds of two thousand iterations, `tarm64osx`:
  `long-exact-sequence-matching` 90 -> 40 ms, `pipelined-requests` 23 -> 10 ms,
  `dense-byte-dispatch` 60 -> 37 ms, `many-small-headers` 59 -> 37 ms,
  `long-method-target-header-spans` 101 -> 85 ms. No workload regresses.
  Downstream, a 530-state HTTP message machine scans a request target at
  27.9 ns/byte where it scanned at 241.9.

  **The emitted text grows about 12%**, and all seven committed goldens move.
  No fingerprint moves: the machine fingerprint is over the IR, which is
  untouched.

- **The emitter's private names carry a `%` prefix.** `%s<id>` and `%dispatch`
  cannot be enumerated in `reserved-member-3` -- a machine's state count has no
  bound -- so instead they are unforgeable: `portable-name?` admits
  `[a-z][a-z0-9-]*`, so no output binding and no declared name can begin with
  `%`. Both guards assert the prefix rather than trusting it.

### Added

- **A threshold for admitting an optimization, derived from the baselines'
  observed variance rather than chosen.** A workload is admissible evidence
  only when its median is at least 20 ms -- above that the observed dispersion
  span is at most 4.3% of the median, below it the span reaches 25% and then
  unbounded. Material improvement is 20% on at least three admissible workloads
  with none regressing; significant regression is 10% on any one.

### Fixed

- **The committed baseline could not be the denominator of anything.** It was
  recorded at one hundred iterations per round, where ten of its twelve
  generated-lane medians are 0, 1 or 3 ms against a one-millisecond clock. It is
  re-recorded at two thousand.

## [0.5.0] - 2026-09-15

### A parser can start in a mode

**Added: a settable field and an embedder-chosen initial at `make-parser`.** A
uint field may be declared **settable**, and a parser built from a machine may
then start that field somewhere other than its declared initial — so two parsers
from one machine can start in two modes (a request/response selector, a
lenient-flags bitset), where before a grammar had to spend entry nodes writing
the mode. Both are optional and existing machines are unchanged:

```
(make-uint-field name width initial settable? label)         ; settable? optional, default #f
(make-parser compiled-machine callbacks user-context inits)  ; inits optional: ((field . value) ...)
```

The `inits` alist overrides the declared initial of **settable** fields only,
range-checked to the field's declared width, and is refused for an unknown or
non-settable field name, a duplicate, or an out-of-range value. It applies at
CONSTRUCTION, so it can never corrupt a field mid-parse — the reason a general
`parser-field-set!` was declined. `parser-reset!` restores the embedder-given
initials, so a mode chosen at construction survives a reset rather than
reverting on the first one. The new accessor `uint-field-settable?` reads the
flag. The interpreter and the generated parser are proved to agree over the
mechanism by `byte-machine.differential.settable`. See [the field
reference](.reference/field-and-overflow.md).

For the downstream consumer this collapses a two-integer mode surface — request
vs response (1 required callback + 3 nodes) and an 11-bit lenient-flags bitset
(11 optional callbacks + 22 entry nodes) — to **two settable field declarations
and one `make-parser` argument**.

### Changed

**Generated-parser ABI bumped 7 → 8.** A machine with a settable field now emits
an optional fourth metadata member — a `(name width)` settable table the
generated `make-parser` range-checks an override against. The member is present
only when a field is settable, so a machine with none emits byte-identically
except the ABI literal (all seven determinism goldens re-baselined; only the
literal moved). A consumer decoding a v8 generated parser must know a settable
machine carries the extra member.

**The verifier gains `settable-consume-counter`.** A settable field may not be a
counted-consume node's counter: its embedder-chosen initial would falsify the
EOF-execution pass's reasoning about a counter's value at the entry state.

## [0.4.0] - 2026-09-14

### A pause carries a reason

**Added: an optional reason on a pause, read through `parser-result-pause`.** A
`pause` node — and a `callback` node whose callback returns `callback-pause` —
may now name an OPTIONAL reason: a declared `error-declaration` (the same
name/code/reason shape an error uses), referenced by name. Construct it through
the existing builders, which gained the trailing argument via `case-lambda`, so
no existing machine changes:

```
(make-pause-node name continuation reason label)      ; reason optional
(make-callback-node name callback reason label ...)   ; reason optional
```

A paused `parser-result` then reports that reason as a `parser-error`-shaped
`(code, reason)` value in a NEW slot, read by the accessor
**`parser-result-pause`** — the first read accessor added to the parser-result
family since v0.1.0. `parser-result-error` stays `#f` for a pause: a pause is
*not* an error and remains resumable, so a slot-only consumer still sees the
paused/errored distinction, and `status` together with the `paused-feed` /
`paused-finish` lifecycle rows are unchanged. The reason survives
resume-and-re-pause — two paused nodes report their two distinct reasons, not
the first one twice. The interpreter and the generated parser are proved to
agree over the mechanism by `byte-machine.differential.pause`. See [the
source-IR reference](.reference/source-ir-and-builder.md#nodes).

### Changed

**Generated-parser ABI bumped 6 → 7.** The emitted paused-outcome's payload
contract moves: its error slot goes from always-`#f` to `#f | ParserError` (the
carried reason, when the pause declares one). A version-6 generated library and
a version-7 runtime refuse each other. A pause that declares no reason still
emits a byte-identical parser but for the ABI version literal — the reason
enters the normalized encoding and the fingerprint only under a presence guard.
Measured through the emitter: a two-node pause machine emits **1,825 bytes**
without a reason and **1,942 bytes** with one declared reason — **+117 bytes**,
the single errs-table entry the reason adds plus its wiring.

## [0.3.0] - 2026-09-13

### The keyword-table node kind

**Added: a `keyword-table` node kind.** A fourteenth IR node kind that
matches one of a set of keywords, *tolerating* proper prefixes — `GET` and
`GET-PARAMETER` may both be entries, and the longer wins when the input reaches
it (`GET` followed by a non-extending byte takes the short keyword, leaving that
byte) — and, per table, folding ASCII case. Construct it through
`(byte-machine graph)`:

```
(make-keyword-table-node name entries no-match eof-target case-insensitive? label)
(make-keyword-entry bytes target label)
```

The walk is greedy, forward, and never backtracks; a matched keyword's span
closes at its own length (the closing byte is not consumed); at end of input a
parked table takes its `eof-target` rather than any keyword. When
`case-insensitive?` is true the match folds `A`–`Z` ↔ `a`–`z` and nothing else;
the verifier rejects two byte-identical entries (`duplicate-keyword`). The
interpreter and the generated parser are proved equivalent over the mechanism by
`byte-machine.differential.keyword-table`, and the interpreter's own walk is
pinned absolutely by `byte-machine.unit.keyword-table`. See
[the source-IR reference](.reference/source-ir-and-builder.md#nodes).

**Generated-parser ABI bumped 5 → 6.** The node lowers to a single compact table
walked at run time by the new `byte-machine-keyword-step/v1` runtime op, not
to one dispatch state per prefix. A machine that uses no keyword table still
emits a byte-identical parser but for the ABI version literal; a
version-5 generated library and a version-6 runtime refuse each other. All six
existing determinism goldens are re-baselined to the version-6 literal, and a
seventh golden (a keyword table) is added.

**Added: the per-table folded-collision rejection, and the HTTP-header
case-insensitivity demonstration.** The verifier now rejects a
*case-insensitive* keyword table whose two entries are equal after ASCII
case-folding (for example `Content-Length` and `content-length`) with a new
diagnostic `case-insensitive-keyword-collision` — the fold-up analogue of
`duplicate-keyword` (which still catches byte-identical entries in either
table). Byte-distinct case variants remain legal in a *case-sensitive* table. A
new lane `byte-machine.differential.keyword-header` proves this on the HTTP
header shape: a case-insensitive table folds `Content-Length`, `content-length`
and `cOnTeNt-LeNgTh` to one target while a case-sensitive one over the same
names recognizes only the canonical bytes, interpreter and generated agreeing
with the generated side asserted absolutely. The verifier now has 32 diagnostic
codes.

**Added: span composition and the measured size win.** A span opened before a
keyword table closes at the **matched keyword's length**, not at a delimiter —
`span[method]="MKCOL"` from the six bytes of `MKCOLA`, the whole
`GET-PARAMETER` when the input reaches it — proved on both executors by
`byte-machine.differential.keyword-span`. And the change's justification,
measured through `byte-machine.unit.keyword-size`: the **47 llhttp method
names** as **one `keyword-table` node emit 2,795 bytes**, versus **96,169 bytes
for the equivalent 242-node byte-dispatch trie** the workaround ships today — a
**34× reduction, 242 generated states to one**.

## [0.2.0] - 2026-09-13

Empty spans are now observable, the first change after v0.1.0, requested by the
downstream `chez-httparse` consumer.

### Changed

- A byte-machine span that opens and closes **having delivered no bytes** now
  invokes its span-data callback **exactly once, with an empty range** (`(f
  parser ctx bv from to)` where `from == to`), so a consumer can tell "an
  optional field was present and empty" from "this field never happened". This
  amends the span contract: a span end (feed-side or at EOF) delivers
  `[mark,cursor)` even when empty, once, when the span has delivered nothing.
  The feed-boundary flush still suppresses empty fragments (an open span is
  still being built), and `parser-finish!` re-anchors the span mark to 0 so
  every empty span closing at EOF is announced uniformly, independent of how
  the input was sliced. - The change is confined to `(byte-machine runtime)`
  internals (a per-span "delivered?" flag and a signature-preserving split of
  the span-fragment step). The **emitted text is byte-identical**, so the six
  determinism goldens do not move and the **generated ABI stays 5** (no bump —
  the contract's shape is unchanged, only its behaviour). No public library
  gains a name.

Consumers pinning byte-machine by gitlink pick this up by moving their pin off
`v0.1.0`, targeting the same generated ABI 5, and re-measuring their traces:
empty spans that previously produced no callback now produce one empty fragment.

## [0.1.0] - 2026-09-12

The first tagged release. byte-machine generates R6RS Chez Scheme byte parsers
from a machine described through the public `(byte-machine graph)` API: verified,
compiled offline, and emitted as a self-contained library that depends only on
`(byte-machine runtime)`. It covers the executable machine, the incremental
feed/finish lifecycle, byte classes and sequences, fields, actions and branches,
callbacks, parser poisoning and spans, counted consumption, and a structural
verifier backed by generative differential testing. The documentation set
(`.reference/`, eleven references) and a runnable example
(`examples/generate-simple-machine/`) ship with it.

**Known open in 0.1.0:**

- **CI verifies one platform.** Only macOS arm64 is verified, and locally; Linux
  amd64, Windows amd64, and Linux arm64 are not verified in this release for lack
  of CI minutes. Cross-platform generation equality rests on six committed
  determinism goldens compared on every run, over the one platform that runs.
- **A failing zero-width machine action reports its error position wrongly.** The
  specified position is a `boundary` at the current stream offset. The broken
  shape needs a fallible zero-width action reached over a reexecute edge, which no
  shipped fixture produces; the callback-failure half of the same rule is correct.
- **`parser-result-next` and `parser-result-consumed` are meaningful only for
  feed-originated results**, and that is not enforced.
- **The verifier's span-topology check is partial**: not every invalid span
  topology is rejected.

What the release contains, in outline:

- **Byte classes, sequences and alternatives.** Byte-class matchers, sequence
  dispatch with prefix lowering, and multiple alternatives, with the verifier's
  ambiguity and cycle analysis.
- **Fields, actions and branches.** Field declaration and slots,
  `parser-field-ref`, field actions and field branches, integer accumulation, and
  the `parser-error` record.
- **Callbacks and poisoning.** Callback and span declarations, indexed binding
  resolution and five public accessors. The callback-invocation node's four
  outcomes route identically in the interpreter and the generated code through
  one shared classifier; an out-of-contract return is a `callback`-domain parser
  error, not a raise; a callback that raises or escapes marks the parser
  `poisoned` through `dynamic-wind`. `parser-state-name` answers in both, which
  takes the generated ABI to version 5 to carry a state-id to source-name table.
- **Spans.** Span-start and span-end node kinds. The verifier proves span topology
  by dataflow over a flat lattice rather than by enumerating paths; the fragment
  rules execute behind one runtime boundary flush. Raw fragment boundaries are
  intentionally schedule-dependent; the coalesced trace is not. Spans open at
  `parser-finish!` and closed on the EOF chain, a reset while parked between the
  span-end substeps, and a reset of a poisoned parser with a span open are all
  covered. A callback/span lifetime reference ships in `.reference/`.
- **Input retention.** The runtime keeps no reference to a fed bytevector after a
  feed returns. The test holds the parser alive across a full collection and drops
  only the fed bytevector, with a negative control that retains on purpose, and
  covers the application-owned carriers — user context, a callback closure, and
  the callback error detail — plus the boundary flush and the mark re-anchor.
- **Counted consumption.** A counted-consume node kind (wire tag 14), executed in
  both lanes: the zero-count test precedes the exhausted-input test, count
  completion wins, and the position kind is carried through a zero-count
  transition. A parser parked on the node resumes on its EOF route. The six
  fragment rules hold over a counted body.
- **Names and labels.** One portable-name grammar,
  `(byte-machine private names)`, shared by the verifier, the emitter and the
  runtime, and enforced at `make-callback-failure`. The label grammar is checked
  over every label carrier, callback and span declarations included, with one
  finding per carrier.
- **Verification.** Reachability walks what an execution can actually occupy —
  byte-reached nodes plus the EOF walk from the parked set — so a node reached
  only by crossing an eof-target and then taking byte edges is unreachable. The
  diagnostic record carries seven fields, adding `diagnostic-severity`,
  `diagnostic-machine`, `diagnostic-declarations` and `diagnostic-path`; eight of
  the thirty codes carry a representative graph path.
- **Generative testing.** A generator draws random machines over all thirteen node
  kinds, and a property differential compares the reference interpreter and the
  compiled executor on the per-schedule result tuple, the fragment/callback traces
  across every input split, and a set of invariants (the lifecycle table, cursor
  arithmetic, field bounds, the span-content anchor). A machine printer renders any
  built machine as constructor calls; a saver turns the first disagreement into a
  self-contained R6RS program that reproduces it; a minimizer shrinks it. Every
  diagnostic has a positive and a negative test; an independent second
  implementation of nine verifier graph rules agrees with the verifier on every
  drawn, rejected and corrupted machine; no declared name becomes a generated
  identifier; and the largest emittable machine compiles and runs under
  `compile-file`.

  golden, `test/fixtures/generated-http-version.golden.sls`, generated by the
  shipped emitter, never hand-written. A branch is the only shape that can
  witness an unstable child order at the branching prefix state. The order in
  question is `trie-put`'s own ascending alist insertion, **not** the
  `list-sort` that orders a byte-dispatch node's transitions: flipping
  `list-sort`'s comparator re-emits this machine byte-identically while it does
  reorder a two-case byte-dispatch node's arms.

  Two limitations. Generated output is not compared byte for byte across
  operating systems and architectures: "deterministic" means byte-identical
  within one process, identical across the source and AOT lanes, and equal to a
  committed golden, so cross-process and cross-platform identity follow
  **transitively** from every lane comparing against the same committed bytes,
  not from a direct measurement. And no lane compiles and executes a machine
  whose only case is a vacuous complement,
  `(make-byte-complement-matcher (make-byte-range-matcher 0 255))` — that
  construct is exercised by the normalizer (`normal-ir-tests.sps`, "a vacuous
  complement lowers to zero transitions") and the verifier (`verify-tests.sps`,
  "a vacuous complement collides with nothing") but never compiled and run.

  Nothing in the normalizer, the emitter, `runtime.sls` or the `/v2` ABI
  changed; existing fingerprints and goldens are byte-identical.
- **The diagnostic record carries severity, machine, declarations and path**
  beside its code, node and edge, and four new accessors are exported from `(byte-machine verify)`: `diagnostic-severity` (`error` for every
  finding; warnings are not yet emitted), `diagnostic-machine` (the machine's
  name, `#f` for the not-a-machine arm), `diagnostic-declarations` (the
  declaration names a finding names beside its node) and `diagnostic-path` (a
  representative graph path — first element, last element and membership are
  what a test should compare) for the eight codes whose finding is about a path.
  The existing accessors are unaffected.

### Changed

- **The verifier rejects two machine shapes it previously accepted.** A machine
  whose entry node *is* a `finish` terminal now reports `non-eof-into-finish`
  — before, one byte returned `finished` without ever being examined. And the
  entry node's own EOF path is now classified like every other, so an entry that
  reaches a `stop` reports `eof-reachable-stop` and one that cycles reports
  `eof-zero-progress-cycle`; before, `entry = a stop node` verified with zero
  diagnostics while the identical property one hop away was correctly rejected.
- The `non-eof-into-finish` check is derived from byte-reachability over every
  node's out-edges rather than written out per node kind, so it covers node
  kinds added later without being extended by hand.
- Diagnostics gain an `edge` field, exported as `diagnostic-edge`, carrying the
  edge role that produced a finding where one applies. It is `#f` for node-level
  findings, so existing `diagnostic-code`/`-node`/`-message` readers are
  unaffected.
- Chez discovery now probes each candidate name in turn instead of committing to
  the first one `find_program` returns. A host with an unrelated `scheme` earlier
  on PATH than its Chez previously failed to configure.
- Version floors are checked for presence before use. `if(x VERSION_LESS "")` is
  false in CMake, so an absent floor accepted every release silently.
- The Chez version is read from after the banner's `Version` keyword rather than
  from the first dotted number anywhere in it.
- Test presets declare a configuration and refuse an empty selection, so the
  documented preset entry point behaves like `make` — on Windows' default
  multi-config generator every test previously reported "Not Run".
- Specifications print their success banner only when nothing failed.
- `MutationRunner` is now generalized on three axes rather than two: it takes
  the staged trees and the verify command as parameters, so a mutation can be
  judged by running a real execution lane rather than only by `cmake -P`;
  gained a reset entry point so a second declaration pass can run under a
  different verify command in the same script; and gained a verify working
  directory, separate from the staged tree. The CMake-layer suite keeps its previous
  behaviour by default on all three axes.
- `byte_machine_mutation` gained optional `EXPECT_STATUS` and
  `EXPECT_OUTPUT_MATCHES`, narrowing "caught" to "caught for the declared
  reason": a nonzero verify-command result whose exit status or combined
  stdout+stderr does not also satisfy the declared expectation is reported
  separately, as caught for the wrong reason, and counted the same as an
  outright miss rather than as a pass.
- `byte_machine_mutation_run` now accumulates a running pass and mutation
  count across every call in a process (`byte_machine_mutation_totals`), and
  both mutation suites compare that total against a count declared next to
  their own header comment, failing loudly on a mismatch, so a dropped pass
  group cannot silently shrink the suite.
- `ByteMachineExpectExit`'s comments and specification illustrate the
  out-of-vocabulary case with Chez's measured exit for a `--script` naming a
  file that does not exist (255); the declared vocabulary remains 0/1/2/3.
- Every library is an ordinary R6RS `.sls` and every test program a plain
  `.sps`. The fingerprint algorithm is its own library,
  `(byte-machine test fingerprint)`, imported by the harness and by the
  build-time expectation alike. A lane's manifest (`SOURCES`) is its program
  plus every library it loads, so every byte of Scheme a lane runs is
  fingerprinted.
- The comment above the `cmake-mutation` lane, which claimed the lane "runs
  in CI", now says it runs under `ctest`.
- The harness adapter derives OS and architecture through pure
  `machine-type->…` functions, tested exhaustively over the Tier-1 machine
  types, and the self-test/bootstrap lanes assert the live values by equality
  when the cell's identity is supplied, replacing the earlier not-"unknown"
  checks.
- `private/normal-ir.sls`'s node-kind dispatch gains an `else` guard that
  raises on an unknown kind; `normal-state-id` is now asserted directly rather
  than only exercised indirectly; `normalize-machine`'s combined
  lowering-and-encoding splits into two focused functions, with the IR
  fingerprint pinned unchanged across the split to prove it is
  behavior-preserving; `runtime.sls`'s `make-parser` v1 branch reads the
  compiled machine through named accessors instead of positional
  `(vector-ref cm 2/3)`; the Scheme mutation suite's Pass 36 assertion tightens
  from the loose `EXPECT_OUTPUT_MATCHES "ok"` to `"not ok"`; and the one-byte
  fixture duplicated across the differential and example test programs
  collapses into one shared fixture. `id-of`'s linear `assq` scan per call is
  left as is until a reproducible compiled benchmark shows a material
  improvement, and `emission-metadata` has no named accessors while no consumer
  exists beyond the tests that construct it.
- Sticky lifecycle rows (`stopped`/`error`/`finished`) now short-circuit at
  the operation entry and synthesize the sticky-repeat result tuple directly,
  instead of re-executing the interpreter/generated loop from a parked
  terminal `current` and relying on that re-execution being idempotent. The
  parser gains a stored-error slot (`runtime.sls` slot 7,
  `parser-stored-error`) so the error row has a value to return without
  re-running anything. This changes no previously correct result tuple, and it
  fixes one case: a repeat feed after a **default-EOF truncation** left
  `current` parked on the exhausted dispatch node rather than past it, so the
  next feed re-ran dispatch and **consumed bytes** instead of returning the
  sticky error tuple. Covered by `runtime-tests.sps`'s "the error row returns
  the stored error after a default-EOF truncation" case.


- **The generated-code ABI is one unversioned constructor, and its version is
  now 3.** `byte-machine-make-compiled-machine` replaces the `/vN` family; its
  first action is the `(= abi-version current-abi-version)` check, so a mismatch
  is reported before any part of the payload is interpreted, and the payload is
  one growable quoted vector rather than a rest-arg, which keeps growth and the
  version check coupled. `/v1` and `/v2` remain exported as tombstones that
  refuse **every** version, so a stale generated file is refused rather than
  accepted. Generation is deterministic and the committed goldens are
  regenerated from the emitter.
- **The canonical normalized encoding is format 2**, carrying the static reason
  of every error declaration the graph **reaches** — an error node's, and the
  machine default-eof error's — and reserving a field-table count of zero. Two
  machines differing only in a reached declaration's reason therefore differ in
  IR fingerprint, without which the fingerprint would stop identifying what was
  emitted. Existing IR fingerprints change once, here.
- **A parser error is a structured record, not a bare code symbol.**
  `parser-result-error` now yields a `parser-error` carrying domain, code,
  reason, detail, public source-node name, state ID, absolute offset and
  position kind. Both executors build it from the same inputs, and the
  differential compares five of those members plus `reason`. The **state ID is
  deliberately excluded** from that comparison and is the one member the two
  lanes may differ on, since an independently interpreted machine need not
  number states as the generated one does. Both still report one.
- **Machines declare unsigned integer fields, and parsers read them.**
  `make-uint-field` takes a name, a width of 8/16/32/64, an initial value and a
  source label, and refuses everything else **at construction** with a contract
  violation rather than a verifier diagnostic, so a machine whose field is out
  of range never exists. The verifier carries only what a constructor seeing one
  field at a time cannot — duplicate field names and names outside the portable
  identifier repertoire, both reported as `invalid-field-declaration`. Slot
  index is declaration index, the normalized IR carries a field table, and
  `parser-field-ref` reads a declared field through either executor. It is
  **read-only and has no mutating sibling** by design: a callback that could
  write a field would bypass the closed IR and invalidate interpreter/generated
  equivalence. An undeclared name raises a contract violation under a new
  `accessor-misuse` code — a caller mistake is not a machine outcome and must
  not arrive as a `parser-error`. The verifier also gained its
  unsupported-IR-version check.

  Machines that declare no fields keep their IR fingerprints and generated
  output unchanged; field-declaring machines get fingerprints of their own. The
  generated library's error table now holds one entry per error declaration the
  graph reaches, so a declaration the graph never reaches is no longer emitted.

- **Machines act on and branch on their fields.** Two zero-width node kinds:
  `make-field-action-node` applies one of seven operations —
  `store`, `clear`, `increment`, `decrement`, `add`, `set-mask`, `clear-mask` —
  and `make-field-branch-node` selects between two mandatory targets on one of
  seven predicates. Both consume no byte. Overflow and underflow are **checked at
  every width and leave the prior value unchanged** — not
  saturated — and route to a declared error target, which the constructor makes
  mandatory exactly when the operation can fail and forbids when it cannot.
  Operand faults are reported by the verifier under a new code,
  `invalid-field-operand`. `parser-reset!` restores every field to its declared
  initial value, and each parser's fields are its own.

  **The EOF-chain walk was rewritten to answer over a set of successors**, since
  a field branch has two: one DFS carrying a path stack for cycles and a global
  completed-set for verdict reuse.

  The arithmetic is **written twice on purpose** — once in the interpreter from
  the source IR, once in the emitter from the normalized table — so a lowering
  bug in overflow checking stays visible to the interpreter≡generated
  differential. No existing machine's encoding moved.

- **Machines read integers out of the input stream.** `make-integer-accumulate-node`
  is an **input-reading** node kind: it consumes digit
  bytes in base 10 or 16 and folds them into a declared field, taking an explicit
  fallback edge on the first non-digit and a mandatory error target on overflow.
  The checked multiply-add tests the bound **before** the multiply, not
  compute-then-check, so it does not rely on host fixnum width, and the
  offending digit is **not consumed**, which is what makes an overflow report
  position kind `byte` at the digit itself rather than `boundary` after it.

  The digit test is rendered as **range comparisons per base**, not one `case`
  group: base 16 has three disjoint ASCII ranges and a single `case` over literal
  bytes cannot express it. Both lanes are compared over **all 256 byte values in
  both bases**.

  **A parse that spans a feed boundary needs no state of its own.** The
  accumulated value *is* the field, which already survives a feed, and the node
  stays parked because its arm returns `need-input` without moving on. Every
  split point of a multi-digit input is driven, not one.

  A fourth committed golden, `generated-accumulate.golden.sls`, pins the emitted
  arm.

  Fixed with it: the emitter credited only dispatch states with the default-EOF
  route, so a machine whose only default-eof consumer was an accumulate node had
  that declaration filtered out of the emitted table and rendering raised on a
  machine the verifier had just accepted. The verifier's EOF analysis now
  covers accumulate nodes: an EOF chain reaching one no longer makes
  `verify-machine` raise, an accumulate naming itself as its own eof-target is
  rejected rather than looping forever in both executors, and an accumulate
  byte edge into a finish terminal is rejected. Every existing golden and IR
  fingerprint is unchanged.

### Fixed

- `MutationRunner.cmake` — the machinery every specification in this tree is
  trusted through — had neither a specification nor a mutation targeting it,
  so the branch that turns a wrong-reason result into a failure could be
  deleted and the CMake-layer suite stayed green. The verdict decision is now
  split out as a pure function, `byte_machine_mutation_verdict` — no
  `execute_process`, no filesystem — with its own specification,
  `MutationRunnerSpec.cmake`, registered so it also runs under
  `ctest --preset no-scheme`. Mutations in `MutationSuite.cmake` break each of
  the pure function's decisions and the registration guard beside it, and the
  specification also stages a real mutation with an unsatisfiable
  `EXPECT_OUTPUT_MATCHES` to prove `byte_machine_mutation_run` acts on a
  wrong-reason verdict rather than computing and discarding it.
- `EXPECT_OUTPUT_MATCHES`'s presence was tested by truthiness rather than
  `STREQUAL ""`, unlike the `EXPECT_STATUS` check one line above it. A
  pattern CMake itself reads as false — `"0"`, `OFF`, `NOTFOUND`, anything
  ending `-NOTFOUND` — is still a regex someone declared, and would have been
  silently unenforced rather than checked.
- `byte_machine_mutation` now refuses `EXPECT_SURVIVES` declared together
  with `EXPECT_STATUS` or `EXPECT_OUTPUT_MATCHES`. A declared survivor is
  judged only by whether the verify command exited zero, so the other two
  would have been parsed, stored, and never consulted — silently inert
  rather than enforced.
- The `WORKING_DIRECTORY`-forwarding conditional in `ByteMachineExpectExit.cmake`
  and `ByteMachineSchemeLane.cmake` was mutated in only one direction —
  `if(arg_WORKING_DIRECTORY)` to `if(FALSE)` — which only the specifications'
  "present" assertions could catch. Their "absent" assertions, proof that the
  keyword does not reach the registrar when no caller gave one, are exactly
  what stops the `CMP0174`-driven conditional-forwarding fix from silently
  regressing to unconditional forwarding, and had no mutation exercising
  them. Both sites now also mutate to `if(TRUE)`.
- `SchemeMutationSuite.cmake`'s poisoned-compiled-object mutation now declares
  `EXPECT_OUTPUT_MATCHES "POISONED-FROM-OBJECT"`, enforcing that the mutated
  run names the sentinel in its banner, its FAIL-CONTEXT line, and its
  summary.
